# Test matrix

## API routes

Generated by a throwaway script (`/tmp/inv/inv.mjs`, not committed): it parses every
`router.<verb>('path')` call in `server/src/adapters/inbound/http/*.routes.ts`, prefixes it with its mount
point from `adapters/inbound/http/index.ts` / `composition/container.ts`, then greps
`server/**/*.test.ts` and `e2e/**/*.spec.ts` for a call of the same verb on a matching path
(`:param` ⇒ wildcard). It is a heuristic (a route covered only through a differently-prefixed
router mount is reported as untested).

**Coverage: 131 routes. Before: 112 with a test, 19 without (the OAuth
`/:provider` pair is a detector false positive). After: every route has at least one test.**

Notes
- `workflow.routes.test.ts` mounts the router at `/api/v1/workflow` (singular); the real mount is
  `/api/v1/workflows`, so the new live-app test exercises the real prefix, auth, org isolation and RBAC.
- Bug found by the new tests: `PATCH /workflows/rules/:id` passed an unvalidated body to SQL, so
  `{priority:"x"}` returned **500**; now validated with zod → 400 (`workflow.routes.ts`).
- `securityFindings.test.ts` asserted the screenshot URL contains the annotation id, which only holds
  for the S3 driver; with the default `local` driver (no S3 env) the URL is an opaque signed
  `/api/v1/screenshots/<token>`. The assertion is now driver-agnostic (test-only fix).
- `screenshotS3.test.ts` skips unless `S3_ENDPOINT` is set (MinIO); not part of the route gap.
